# Research: why the agent fails, and what can move the score (2026-10-02)

After v1 (dev 6/33, leaderboard 0.12) and the v2 sampling/prompt batch (dev 6–8/33), a research
pass looked at every failure and every lever we have. It used 17 parallel agents:
- 6 diagnosed the 27 v1 failures one by one (trace, our patch, hidden-test output, gold patch);
- 4 researched harness levers, competitors, the time budget and model quirks;
- 3 designed experiments (prompt/budget, architecture, fine-tuning), each challenged by a skeptic;
- 1 synthesized the plan.

Everything was read-only. All claims come from the harness source, the traces or the forum. The
full machine output is kept outside the repo (it is large).

## Where we stand

- **Leaderboard arithmetic.** The public set has 58 tasks, and scores are truncated, not rounded.
  0.12 = 7 tasks, 0.15 = 9, 0.17 = 10, 0.24 = 14. One task is 0.017. A single submission varies by
  about ±2.5 tasks from luck alone.
- **The 0.15 cluster is mostly one public config on good draws.** Identical copies of the public
  "coder + analyzer" bundle scored 0.06–0.15. The 0.24 team has published nothing.
- **Dev ceiling.** 15 of the 33 dev tasks cannot be passed from the issue text (hidden tests check
  exact strings, new modules, docs snapshots, or behaviour described only in linked issues). They
  passed 0 of 75 times across 5 runs. 6 tasks pass almost always. **The 12 remaining tasks are
  where configs differ** (`eval/fairness.json`).

## What actually goes wrong

| Problem | Evidence | Fix being tested |
|---|---|---|
| **Garbled `edit_file` calls.** Quote-heavy edits (dicts, docstrings, URLs, HTML) come out with arguments run together, e.g. `"filepath": "x.py\`,new_string:"`. The tool rejects them and the model resends the same broken call. | 143 of 183 v1 `edit_file` calls were malformed. fastapi_14964 passed 8 of 9 hidden tests and lost only because its last edit never parsed. | Edit through a Python script in `run_command` (one string argument, which almost never breaks); v3b removes `edit_file` entirely |
| **Repetition loops** | 34% of v1 calls repeated the previous call exactly | Temperature 1.0 (v2a: 12%). Prompt rules alone did nothing (v2b: 37%) |
| **Forgetting after compaction.** When the history passes ~14k tokens it is summarized, tool results are dropped, and the model loses track. | Compaction hit 13 v1 tasks and 20 v2a tasks; almost none of those passed | Pin the issue text in the system prompt with `{problem_description?}`, which ADK re-inserts on every call |
| **Wrong location.** The task message's directory tree is cut off before the package folder. | rich_4077 never saw `file_proxy.py` | First call lists the source files with `git ls-files` |
| **Testing the wrong copy** (src/ layouts) | requests_7427: `import requests` loaded an installed copy that already had the fix, so the agent concluded nothing was wrong | Check `pkg.__file__`; the dev bench now installs the repo in editable mode like the scorer |
| **Adding extra things.** The hidden tests compare whole dicts and messages. | fastapi_14791 added one extra key | "Copy the neighbouring code; add nothing the issue does not ask for" |
| **Never running the tests** | 0 pytest calls in the wrong-fix traces | Find and run the covering test file before submitting |
| **Stray files** | 6–12 `repro.py` files per run end up in patches; `write_file` cannot write to /tmp | Create scratch files with a `cat` heredoc under /tmp |
| **An undeclared tool zeroes the task.** The harness advertises `get_code_subgraph`, which v1 did not declare. | `google/adk/flows/llm_flows/functions.py` raises on unknown tools | Declare it |

Time is **not** the bottleneck: the mean task takes about 2 minutes of the 4.5 allowed. A 120-task
run projects to about 5.5 h of the 12 h.

## What the submission format allows (and does not)

- **Allowed:** an LlmAgent root with tools; sub-agents as tools (`agent_tool`), whose `output_key`
  can save notes into the instructions; `generate_content_config` (temperature, top_p, top_k,
  max_output_tokens, thinking); the four `eval_config.yaml` budgets; LoRA adapters.
- **Rejected or silently ignored:** `planner`, `global_instruction`, `static_instruction`,
  `code_executor`, `output_schema` (the schema forbids extra keys); callbacks (dropped);
  presence/frequency penalties (vLLM applies them within one reply only, so they cannot stop
  repeats across turns).
- **Risky:** workflow roots (Sequential/Loop/Parallel) break compaction; sub-agent sessions are
  never compacted, so they can overflow and zero the task; thinking at the root costs about 7 s
  per 256 thought tokens per call at ~36 tokens/s.

## Experiments rejected, and why

- **Reviewer sub-agent before submitting.** In the sandbox, FastAPI test setup fails on 2 of the 6
  always-passing tasks, so it would wrongly reject good fixes.
- **Investigator/scout sub-agent.** Its uncompacted context can overflow and zero tasks.
- **Raising the time limit above ~5 minutes.** The worst case would exceed 12 h, which fails the
  whole submission.
- **Copying the public 0.13–0.15 bundles.** They are the same agent on lucky draws.
- **Hint-conditioned self-distillation.** Hints leak test names the agent could never know.

## The v3 batch (running)

All four configs build on v2a (temperature 1.0, top_p 0.95, top_k 64) and declare `get_code_subgraph`:

| Config | Change | Question |
|---|---|---|
| `v3d_full` | All fixes below, plus 50 tool calls | Do the fixes add up? This is the submission candidate |
| `v3a_hyg` | Tool mechanics only: script edits, `nl`/`sed` reads, /tmp heredocs, timeouts | Does the model adopt script edits, and do garbled calls drop? |
| `v3c_loc` | Localize / reproduce / verify rules only | Do the wrong fixes drop? |
| `v3b_noedit` | `edit_file` and `write_file` removed | The structural fallback if the model keeps choosing `edit_file` |
| `v2a_rerun` | v2a again | How noisy is a temperature-1.0 run? |

Decision rule for submitting: v3d_full needs at least 8/33, no undeclared-tool or overflow errors,
at least 5 of the 6 core tasks kept, and fewer garbled calls than v2a. Otherwise submit v2a.
Compare runs with `scripts/compare_runs.py`.

## Fine-tuning path (gated)

1. **FT-0** (no submission needed). A 30-minute notebook measures the KV cache and decode speed
   with one rank-16 adapter, and checks that the adapter actually changes the outputs. The admin
   says the "~7.6k KV with any LoRA" bug is fixed, but nobody has measured it.
2. **FT-1, self-rejection-sampling.** Run the best prompt config 4× on the 72 train tasks. Keep the
   trajectories that pass the hidden tests. Train a rank-16 LoRA on only the model's own turns
   (loss masking), at most 2 epochs. Ship it only if it beats the same prompt without the adapter
   on dev.

   Go ahead only after the prompt-level fixes are measured, and only while garbled calls stay
   above ~5% or repeats above ~15% (things training can teach). The expected gain is +0 to +2
   dev tasks. Its main value is learning.
